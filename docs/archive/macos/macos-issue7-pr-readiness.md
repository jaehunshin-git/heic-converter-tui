# 이슈 #7 PR 준비 기록

이 문서는 PR #9 준비 시점인 **2026-10-11의 역사 기록**이다. 아래 테스트 수와 실기
결과·미검증 항목은 당시 상태를 보존하며 현재 완료 여부를 뜻하지 않는다. 특히 당시
Photos HEIC 게시 결과가 현재 Photos 보관함 URL의 지원을 보장하지 않는다.
최신 결과와 테스트 수는 [남은 검증 후속 기록](macos-issue7-remaining-validation.md)을 따른다.
구현 중 바뀐 계약과 현재 이슈 종료 조건은 [변경 계약 감사](macos-issue7-scope-audit.md)를 따른다.

## 현재 후속 범위

Photos 자산 참조 메타데이터(`com.apple.photos.object-reference.asset`)와
`.photoslibrary` 내부 파일 URL이 함께 있는 입력은 종료 후 전체
표현의 복구를 보장할 수 없어 지원을 제한한다. raw HEIC가 있어도 전체 입력을 게시하지
않으며 보관함 URL 없는 raw HEIC 단독 지원은 유지한다. 파일 약속은 표현 데이터를
공급자에게 요청하기 전에 거절한다.

사용자가 미다운로드로 지정한 실제 iCloud 사진의 드래그에서 파일 약속과 `public.jpeg`,
일반 복사에서 HEIC 없는 JPEG raw를 관찰했다. 타입 관찰에는 공급자 요청을 사용하지
않았고 다운로드 상태의 독립 검증은 수행하지 않았다. JPEG 일반 복사는 앱 실행·정상
종료 뒤 전체 표현의 타입·바이트·세대가 보존됐다.

후속 범위에는 Python 코어의 HDR 대표 인덱스 선택 수정도 포함된다. 합성 다중 HEIC의
대표 인덱스 1에서 16비트·PQ HDR PNG와 메타데이터 정책을 검증했으며 CLI/TUI 및 기존
SDR fallback 정책과 PyPI 버전 0.3.0은 유지한다. 카카오톡 후속 실기와 최신 검증 집계는
[후속 기록](macos-issue7-remaining-validation.md)을 따르며 여기서는 완료로 단정하지 않는다.

## PR #9 변경 결과 (2026-10-11)

HEIC를 복사하면 설정한 JPEG/PNG로 자동 변환해 기존 붙여넣기에 준비한다.
스냅샷·복사 세대·일괄 게시로 원본과 새 복사를 보호하며 정상 종료 때 원본을 복구한다.
좌클릭 패널에는 현재 파일과 상태만 두고 옵션은 별도 설정 창으로 옮겼다.
매 실행은 자동 변환이 켜지며 우클릭 메뉴로 해당 실행만 일시정지·다시 시작한다.
변환 알림, 작은 콘텐츠 맞춤 패널, 사진 클립보드 아이콘, 포커스 이동 시 닫힘을 적용했다.
PR #9 준비 당시 Python 코어·CLI/TUI와 버전은 변경하지 않았다. 앱과 Python 패키지의 배포 검증을 분리했다.

## 실제 앱 검증 (2026-10-11)

환경은 macOS 27.2 arm64, Finder와 Photos, 카카오톡 26.8.0이다.
합성 사진은 로컬 검증 폴더에서 생성했다. Photos에는 합성 사진 3개를 전용 검증 앨범에
가져와 한 장만 뒤집기 편집했다. 기존 사진과 보관함 설정은 변경하지 않았다.
카카오톡은 나와의 채팅의 전송 전 미리보기까지만 확인하고 취소했다.
일반 클립보드는 검증 전 전체 표현을 비공개 로컬 파일에 보존한 뒤 복구를 요청했다.
Photos 동영상 포스터의 사진·메타데이터 4타입은 바이트가 일치했다. 원래 파일 URL은
복구 도구 실행 중에는 있었으나 도구 종료 뒤 사라져 전체 표현의 복구로 판정하지 않는다.
개인 사진·클립보드 데이터·자산 식별자를 저장소나 배포물에 넣지 않았다.

| 입력·대상 | 확인 결과 |
| --- | --- |
| Finder HEIC 1개 → Finder | JPEG 1개, 중복 없음 |
| Finder HEIC 3개 → Finder | JPEG 3개, 중복 없음 |
| HEIC 3개 + JPEG·PNG·텍스트 파일 → Finder | 총 6개, 비HEIC 파일 SHA-256 일치 |
| 변환 JPEG 1개 → 카카오톡 | 파일 URL 선택, 전송 전 파일 1개 표시 |
| 혼합 6개 → 카카오톡 | 전송 전 파일 6개 표시, 중복 없음 |
| Photos 원본 HEIC 복사 | 자산 종류 1과 raw HEIC 확인, 수정 후 JPEG 게시 |
| Photos 합성 원본·편집 사진 복사 | JPEG 표현, HEIC 재변환 없이 보존 |
| Photos 합성 원본·편집 혼합 3장 → Finder | JPEG 항목 3개가 파일 3개로 붙음 |
| Photos MOV 복사 | 자산 종류 2의 JPEG 포스터, 변환 제외 |

## PR #9 전에 수정한 결함

- 클립보드 항목 조회가 실패하면 참조 부재를 단정하지 않고 게시 결과 파일을 보존한다.
- 원본 이름이 255바이트여도 내부 staging 이름을 200바이트 이내로 제한해 worker의
  원자 저장 파일명 예산을 확보한다. 표시·원본 복구는 원래 이름을 유지한다.
- Photos 원문 HEIC가 있으면 Photos URL의 물질화나 확장 속성 조회를 기다리지 않는다.
  실제 조사에서 기존 앱의 메인 스레드가 `getxattr`에서 수 분간 대기한 것을 확인했다.
- POSIX 메타데이터로 일반 파일을 검증하고 dataless 파일은 열기 전에 거절한다.
  실패 미리보기와 비HEIC 항목도 위험한 파일 URL을 썸네일에 전달하지 않는다.
- 패키징은 HFS+ UDZO를 사용하고 이미지 생성·GUI 준비·검증 단계에 시간 제한을 적용한다.

## PR #9 검증 근거

- Python 회귀 136개와 Ruff 통과.
- Swift XCTest 95개: 모델 23개, worker 3개, ConverterKit 69개.
  매 실행 활성화·legacy 꺼짐 무시·일시정지 결과 보존·재개 후 완료 문구 복원을 포함한다.
- 실제 worker의 JPEG/PNG·255바이트 ASCII/한글/emoji·중복 입력 변환 smoke 통과.
- 앱·DMG, arm64 Mach-O 44개·서명·로더, 사용자 Python 없는 환경의 SDR/HDR 검증.
- wheel/sdist의 영문 설명·버전·허용 목록 검증. Python 배포물에는 macOS 전용 소스와
  개인 사진을 포함하지 않는다.
- macOS 15/26 Apple Silicon CI가 커밋 `bdbde95`에서 모두 통과했다.
  Python 136개·Swift 93개·Ruff·앱 빌드·DMG 설치 smoke·wheel/sdist 검증과
  두 환경의 산출물 업로드를 포함한다.
  [GitHub Actions 실행 기록](https://github.com/jaehunshin-git/heic-converter-tui/actions/runs/38128156256).
- 별도 named pasteboard 종료 비교 144조건에서 합성 URL·Photos 메타데이터·raw의
  타입·바이트·세대가 보존됐다. 실제 저장소의 capture→publish→shutdown 후 프로세스가
  끝난 합성 혼합 입력도 보존됐다. 실제 Photos의 일반 클립보드 관찰을 대신하지 않는다.

## PR #9 당시 완료로 표시하지 않은 항목

- iCloud 미다운로드 사진의 실기: Photos가 raw를 제공할 때의 처리는 회귀와 실기 HEIC로
  확인했으나, 실제 자산의 다운로드 상태는 확인하지 않았다. 보관함 저장 설정을 바꾸지 않았다.
- Photos 드래그 파일 약속의 실기: 일반 복사 관찰과 합성 promise 거절 테스트로 대체하지 않는다.
- 카카오톡 실제 전송·수신: 붙여넣기 준비 검증과 구분한다.
- 실제 Photos 파일 URL의 종료 후 보존: 독립 복구 도구 종료 후 URL 타입이 사라지는
  현상을 관찰했다. 원본 파일의 POSIX 존재 확인은 성공했고 단순 flush로 해결되지 않았다.
  합성 조건에서는 재현되지 않아 권한·서버 처리를 원인으로 단정하지 않는다.
  앱 자체 정상 종료의 Photos URL 보존 실기는 추가 확인이 필요하다.
- index 0이 대표 이미지가 아닌 다중 이미지 HEIC의 HDR PNG: 기존 코어 범위이며 미검증.

## PR #9 제출용 설명 (2026-10-11 당시)

제목: `feat(macos): HEIC 자동 클립보드 변환과 미니멀 메뉴바 UI`

HEIC 복사 후 수동 변환 없이 기존 붙여넣기로 JPEG/PNG를 전달하도록 macOS 앱을 바꾼다.
원본 스냅샷과 복사 세대로 전체 게시를 보호하고, 실패·새 복사·끄기·종료 시 유효하지 않은
결과를 게시하지 않는다. MOV와 Photos 동영상 포스터는 변환하지 않는다.

좌클릭 패널을 현재 파일·상태로 줄이고 설정을 별도 창으로 옮겼다.
일시정지·다시 시작은 우클릭 메뉴에 두며 매 실행은 자동 변환이 켜진다.
메뉴 아래의 진행·완료·실패 알림과 콘텐츠에 맞는 패널 높이, 포커스 이동 시 닫힘을 추가했다.

검증은 위 자동 테스트와 Finder/Photos 실기, 카카오톡 전송 전 미리보기다.
미다운로드 iCloud·Photos 드래그·실제 채팅 전달과 Photos URL의 종료 후 보존은
미검증 또는 관찰된 제한으로 명시한다.
이슈 #7의 전체 완료 판정과 자동 종료는 남은 수용 검증과 분리한다. `Refs #7`.
