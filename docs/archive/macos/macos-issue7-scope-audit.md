## 실제 입력의 검증 한계와 종료 조건

Photos가 항상 원문 HEIC를 제공하거나 모든 입력을 변환해야 한다는 요구는 원문에
없다. 원문은 실제 복사 형식 조사와 안전하게 복구할 수 없는 표현의 거절을 요구한다.
따라서 보관함 URL의 안전 거절과 파일 약속 수신 미지원은 그 계약에 맞는 지원 제한이다.
Photos 직접 드롭 UI, 파일 약속 수신, 새 보관함 권한·내보내기 기능을 추가하는 작업은
종료를 위해 새로 요구하지 않는다.

사용자가 미다운로드로 지정한 iCloud 사진의 일반 복사는 HEIC 없는 JPEG였고,
드래그는 JPEG와 파일 약속이었다. 일반 복사 보존과 드래그 타입 분리 조사를 수행했다.
다운로드 상태를 독립 확인하거나 iCloud 전용 HEIC 변환 성공을 검증했다고 표시하지
않는다. 원문의 “조사 결과에 따라 검증”에 대해 위 관찰과 보존 결과·한계를 기록하며,
모든 Photos/iCloud 조합의 성공을 새 종료 조건으로 추가하지 않는다.

카카오톡은 허용된 합성 사진만 나와의 채팅에 실제 전송했다. 다른 상대·기기 수신,
서버의 원본 바이트 보존까지 검증했다고 표시하지 않는다. 이슈 원문의 실제 이미지/파일
붙여넣기와 대상 앱별 제한 기록에 대한 근거는 단일·혼합 전달 실기와 위 제한이다.

## 변경 계약 이외의 종료 조건 재검토

독립 코드·검증 감사에서 자동 변환·혼합 보존·세대·종료 복구·임시 파일·HDR·CLI/TUI·
배포 구성의 추가 필수 코드 결함은 발견하지 못했다. Photos 안전 거절은 원문 계약에
부합하며 iCloud 다운로드 상태 미확인 한계도 유지한다.

설정 기본값 복원은 기존 `onConflict`를 `rename`으로 바꾸고 있었다. 이는 숨겨진
legacy 값을 보존한다는 현재 계약과 불일치한다. 이번 PR에서 화면에 표시한 형식·품질·
압축·메타데이터만 초기화하고 legacy 충돌 정책·저장 위치·일시정지 상태를 유지하도록
보완하며, 저장값과 클립보드 세대·worker 비실행까지 회귀로 확인한다.

수정 전 기존 초기화 동작에서 새 회귀 1개가 `overwrite`/`skip`의 메모리·저장값 비교
4개 assertion에 실패했다. 수정 후 같은 회귀와 모델/worker 30개가 통과했다.
기본값 보완 시 Kit 76개와 합쳐 Swift 106개였으며 Python pytest 163개·Ruff, 앱/DMG·설치 복사본·
내장 worker SDR/HDR·arm64 서명/로더 검증도 통과했다. README 변경 후 wheel/sdist의
영문 메타데이터와 허용 목록을 재검증한다.

**16번의 기본 키보드 접근성 구현·검증 공백은 이번 PR에서 해소했다.**

- 네이티브 앱 메뉴에 `⌘⇧P` 일시정지·재개, `⌘1` 패널 표시, `⌘,` 설정,
  `⌘W` 창 닫기, `⌘Q` 정상 종료를 연결했다. 읽기 전용 목록은 방향키·Page Up/Down·
  Home/End를 지원하고 수정 키가 있는 앱 단축키와 Tab·Escape·Space를 가로채지 않는다.
- 실제 UI 입력으로 닫기 버튼 Space·패널 Escape, 목록의 Home/End·Page Down·방향키,
  `⌘⇧P`의 일시정지·재개, 설정 Tab·Shift+Tab·형식·JPEG 품질·PNG 압축·메타데이터·
  기본값 복원을 확인했다. macOS 전체 키보드 접근이 켜진 상태이며 시스템 설정은 바꾸지 않았다.
- 합성 전용 보드·설정의 릴리스 앱에서 Finder의 앱 선택 후 `⌘O`로 실행 중인 앱을
  다시 열어 패널에 진입했다. 앱의 일반 재활성화와 명시적인 재열기를 구분한다.
- 앱 smoke는 액션 직접 호출과 별개로 `NSApp.postEvent`로 키 이벤트를 앱 큐에 넣는다.
  `⌘1` 멱등 표시·`⌘⇧P`·End/Home·실제 목록 responder의 Escape·`⌘,`·패널/설정 `⌘W`를 확인하며

- 스크롤의 양 좌표계·상하 경계·단축키 미소비 회귀 2개를 추가했다. Swift 총 108개
  (Kit 76+모델 27+worker 3+키보드 2), Python 총 163개와 앱·DMG·설치본 검증이 근거다.

Control+F8/Fn+Control+F8의 OS 상태 메뉴 이동, 모든 접근성 설정 조합과 VoiceOver 낭독
성공까지 검증했다고 주장하지 않는다. UI 도구는 Fn 키를 지원하지 않았다. 확인한 마우스
없는 진입 경로는 Finder 재열기이며 OS별 모든 진입 경로를 새 종료 조건으로 늘리지 않는다.
설정 저장은 기존 모델의 저장·재로드 회귀와 실제 컨트롤 값 변경으로 확인했다.
전체 키보드 접근이 꺼진 모든 모드에서 모든 컨트롤의 Tab 이동을 보장한다는 주장도 없다.

키보드 접근성이 없는 것으로 드러난 결함을 남겨 놓고 이관한 판정이 아니다. 기본 경로를
구현하고 실제 동작과 자동 회귀를 확인했으며, 코드·실기 감사에서 #7을 추가로 막는 필수
항목은 발견하지 못했다. 최신 필수 CI가 통과하면 PR에 `Closes #7`을 연결한다.
