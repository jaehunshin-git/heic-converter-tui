# macOS CI 산출물 저장량 개선

> 저장량 정리 후 확정한 [제품별 저장소 분리 결정](../../decisions/2026-10-18-product-repository-split.md)에 따라
> 앱 CI의 담당 저장소는 `heiccy`가 된다. 아래 artifact 정리·보관 정책과 당시 검증 결과는 보존하며,
> 실제 CI 분리와 기존 앱 CI 중단은 대체 검증 경로를 확인한 뒤 별도로 수행한다.

## 작업 범위와 순서

2026-10-18 KST에 확인한 저장량과 사용자 승인에 따라 다음 순서로 진행한다.

1. 기존 비공개 저장소의 최신 `main` 성공 빌드 결과 2개를 보존하고, 앞서 조회한
   오래된 artifact 208개만 정리한다. 삭제 직전에 저장소·커밋·보존 대상을 다시 확인한다.
2. 일반 push·PR의 빌드와 검증은 유지하면서 artifact 업로드를 생략한다.
   수동 실행 결과는 3일, `macos-v*` 태그 push의 릴리스 후보는 14일 보관한다.
3. 브랜치 push는 `main`으로 제한하고 PR·기존 태그·수동 실행 트리거를 유지한다.
4. 워크플로 정적 검사, 이벤트별 업로드 조건, 기존 두 OS 릴리스 검증을 확인한다.

커밋·push·PR·태그·릴리스는 별도 단계다. 공개 `heiccy`와 저장소 설정은 변경하지 않는다.
공개 저장소 `main`의 CI 전환을 완료하기 전에는 비공개 CI를 중단하지 않는다.

원격 artifact 삭제는 완료했다. 위 항목은 저장 정책의 로컬 검증 기록이며,
새 정책으로 GitHub Actions나 macOS 빌드를 실행한 결과와 구분한다.
실제 정책 적용 여부는 원격 `main` 반영 후 실행에서 확인한다.
공개 저장소나 CI 활성화 설정은 변경하지 않았다.

## 재개 점검

재개 시 `git status --short`, 최근 커밋, 원격 `main`을 대조해 반영 상태를 확인한다.
완료한 삭제를 반복하지 않는다. 새 artifact가 있다면 생성 시점과 용도를 별도로 확인한다.
원격 반영 뒤 일반 push·PR의 업로드 생략과 필요한 수동·태그 실행을 검증한다.
보관 기간 변경은 새로 업로드하는 결과에만 적용된다.

실제 저장량 감소와 이번 달 누적 사용량은 다르다. GitHub의 사용량 표시 갱신에는
6~12시간이 걸릴 수 있으며 이미 누적된 사용량은 삭제로 소급 취소되지 않는다.
[GitHub Actions 사용량 집계 안내](https://docs.github.com/en/billing/concepts/product-billing/github-actions)를 참고한다.
