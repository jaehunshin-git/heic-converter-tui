# macOS 자동 클립보드 변환 계약

## 구현 및 배포 상태

[이슈 #7](https://github.com/jaehunshin-git/heic-converter-tui/issues/7)은 로컬 소스와 앱/DMG로 구현했으며 미릴리스 상태다. 이 문서는 구현한 소스의 동작 계약과 실제 앱 검증 범위를 기록한다. 기존 릴리스나 설치된 DMG가 아래 기능을 제공한다는 의미가 아니다. 로컬 자동 검증 결과는 아래에 기록하며 수신 앱의 실기 호환성과 구분한다.

PR #9의 2026-10-11 변경 범위는 macOS 앱이며 당시 Python 변환 코어는 수정하지 않았다.
현재 후속 범위에는 Photos 입력 보호와 Python 코어의 네이티브 HDR 대표 이미지 선택 수정이
포함된다. CLI/TUI의 조작·출력·SDR fallback 정책은 유지한다. 앱 버전·DMG 파일명 검증을
PyPI 버전에서 분리했으며 `pyproject.toml`과 Python 패키지 버전 0.3.0은 유지한다.
최신 결과와 테스트 수는 [남은 검증 후속 기록](macos-issue7-remaining-validation.md)을
따른다. 구현 중 바뀐 계약과 이슈 #7의 체크리스트별 종료 판정은
[변경 계약 감사](macos-issue7-scope-audit.md)를 따른다. 릴리스 여부는 별도 배포 기록으로 확인한다.

## Apple 공식 pasteboard 계약

- [Pasteboard Concepts](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/PasteboardGuide106/Articles/pbConcepts.html): pasteboard는 여러 항목을 담고 각 항목은 UTI별 여러 표현을 제공한다. 수신 앱은 지원하는 항목과 표현을 선택한다. 일반 복사와 드래그는 구분되며 지연 제공 표현도 존재한다. 이 자료는 보관 문서이므로 현재 API와 함께 참고한다.
- [NSPasteboard](https://developer.apple.com/documentation/AppKit/NSPasteboard): `pasteboardItems`는 전체 항목을 제공한다. pasteboard 수준 `setData`는 첫 항목에 쓰므로 전체 항목 보존을 대신하지 못한다. `clearContents`와 `writeObjects`는 별도 호출이다.
- [readObjects(forClasses:options:)](https://developer.apple.com/documentation/appkit/nspasteboard/readobjects%28forclasses%3Aoptions%3A%29): 각 항목에서 요청한 클래스 중 읽을 수 있는 첫 클래스에 맞는 객체를 만든다. URL만 읽은 결과를 원본 전체 스냅샷으로 간주할 수 없다.
- [changeCount](https://developer.apple.com/documentation/appkit/nspasteboard/changecount): 소유권 변경 감지에 사용하는 세대 기준이다. 게시 전 확인이 원자적 비교·교환이나 서버 트랜잭션을 제공한다는 의미는 아니다.
- [NSPasteboardItem](https://developer.apple.com/documentation/appkit/nspasteboarditem): 항목별 타입과 데이터를 다루는 API다.
- [NSFilePromiseReceiver](https://developer.apple.com/documentation/appkit/nsfilepromisereceiver): 파일 약속 수신 API다. Photos의 일반 복사가 항상 파일 약속 또는 원본 HEIC라는 근거로 사용하지 않는다.

**구현 설계에 대한 추론:** 사진 하나는 하나의 항목에 결과 파일 URL과 JPEG/PNG 이미지 표현을 함께 게시하는 구조로 다룬다. 필요한 TIFF 대체 표현도 같은 항목에 둔다. URL과 이미지 데이터를 별도 항목으로 추가하지 않아 논리적인 항목 수를 유지한다. 이 구조만으로 Finder·카카오톡의 다중 전달이나 중복 방지를 보장하지는 않는다.

## 지원 입력과 보존 범위

지원 대상은 파일 URL로 제공되는 읽기 가능한 로컬 일반 `.heic` 파일과 원문 `public.heic` 이미지 데이터다. 확장자는 대소문자를 구분하지 않는다. 폴더, 심볼릭 링크, `.heif` 및 일반 JPEG/PNG·TIFF 이미지를 HEIC 변환 대상으로 취급하지 않는다. 파일명이나 타입 표시만으로 실제 HEIC 디코딩 성공을 보장하지 않는다.

변경 전에 항목별 타입·데이터와 순서를 스냅샷으로 확보하고 원본 복구 가능성을 확인한다. 비HEIC 파일·텍스트 및 보존 가능한 다른 표현은 항목 순서와 데이터를 유지한다. 변환 항목의 HEIC 표현은 결과 표현으로 바꾸되, 함께 있던 표현은 의미와 복구 가능성을 검토해야 한다. 원본을 가리키는 표현을 무조건 결과와 함께 남겨 수신 앱이 원본을 선택하도록 만들지 않는다.

파일 약속, 읽을 수 없는 표현, 공급자나 외부 상태에 의존해 안전하게 복구할 수 없는 표현이 있으면 자동 변경을 진행하지 않고 지원하지 않는 상태를 표시한다. 타입 목록만 저장하거나 읽기에 성공한 일부 표현만 저장한 것은 전체 복구 가능성의 증거가 아니다. 지연 제공 표현의 바이트 확보만으로 파일 약속 계약까지 복구된다고 가정하지 않는다.

파일 약속 타입이 하나라도 있으면 전체 항목의 타입을 먼저 검사해 표현 데이터나 URL을
공급자에게 요청하기 전에 전체 입력을 거절한다. Photos 자산 참조 메타데이터
(`com.apple.photos.object-reference.asset`)와 `.photoslibrary`
보관함 내부의 파일 URL(`public.file-url` 또는 `public.url`)이 함께 있는 입력도 정상 종료
후 전체 표현의 복구를 보장할 수 없어 지원하지 않는다. raw HEIC가 함께 있어도 이 보호를
우회하지 않으며 다른 HEIC가 섞여 있어도 전체 입력을 게시하지 않는다. 보관함 내부 파일과
메타데이터를 조회하거나 썸네일로 열지 않는다. 보관함 URL 없는 raw HEIC 단독 입력은
계속 지원한다. 보관함 원본이 필요하면 내보낸 파일을 Finder에서 복사한다.
아래 동영상·사진 분기보다 보관함 URL의 전체 입력 거절이 먼저 적용된다.

HEIC가 없는 내용은 재인코딩하거나 게시하지 않는다. 보존 계약과 수신 앱이 실제로 붙여넣는 항목은 별개다. 특히 텍스트를 보존해도 이미지 수신 앱이 텍스트까지 함께 붙여넣는다고 보장하지 않는다.

동영상 타입, 로컬 MOV 등 동영상 URL, Photos 자산 참조의 `mediaType=2`는 함께 있는
JPEG/HEIC 미리보기보다 우선한다. 해당 항목의 이미지 표현을 변환 입력으로 사용하지
않고 모든 표현을 보존하며 UI에서 동영상·변환 제외로 표시한다. 로컬 `public.url`도
파일 원본으로 취급한다. 다른 항목의 HEIC 사진은 계속 변환할 수 있다.
Photos의 `com.apple.photos.object-reference.asset` plist는 현재 관찰한 메타데이터다.
`mediaType=1`만 사진으로 허용하고 필드가 없거나 형식이 바뀌면 자동 변환하지 않는다.
사진 보관함 권한 요청, 자산 조회, 원본 내보내기를 실행하지 않는다.

실제 확인한 Photos 동영상 항목은 MOV 원본 URL 없이 JPEG 포스터 파일 URL을 제공했다.
이 표현을 그대로 보존해도 원본 MOV를 붙여넣는 기능이 생기지는 않는다. 원본 파일은
[Photos의 무수정 원본 내보내기](https://support.apple.com/ko-kr/guide/photos/pht6e157c5f/12.0/mac/27)로
확보할 수 있다. 실제 수신 앱의 표현 선택은 별도 검증 대상이다.

## 자동 처리와 세대 보호

자동 변환은 매 실행 켜진 상태로 시작하고 현재 클립보드의 지원 HEIC도 처리한다. 일시정지는 해당 실행에만 유지하며 다시 시작하면 현재 입력을 처리한다. 기존 설정에 저장된 활성 상태는 실행 상태로 사용하지 않는다. 0.25초 간격으로 변경을 확인하며 접근이 거부되면 자동 읽기를 중단하고 상태를 안내한다. 권한을 우회하거나 붙여넣기 단축키를 가로채지 않는다.

작업은 원본 클립보드 세대와 변환 옵션을 고정해 시작한다. 모든 대상 HEIC가 성공했을 때만 결과 항목 전체를 게시한다. 하나라도 실패하면 부분 결과를 게시하지 않고 원본 클립보드를 유지한다. 새 복사·취소·끄기·종료로 무효화된 작업은 게시하지 않는다. 완료 직후와 게시 직전에도 세대를 확인하고 자체 게시 세대는 다시 변환하지 않는다.

세대 검사와 쓰기 사이에도 외부 변경이 가능하므로 쓰기 결과와 게시 후 소유권을 확인한다. 복구 과정에서도 다른 앱이 새로 복사한 내용을 덮어쓰지 않는 조건이 필요하다. 이는 세대로 보호하는 일괄 게시 계약이며, Apple API가 원자적 트랜잭션을 보장한다는 주장이 아니다.

복사 직후부터 완료 전까지 기존 ⌘V는 원본을 전달할 수 있다. 완료 후에도 어떤 표현을 선택하는지는 수신 앱의 동작에 달려 있다. 기능을 끄면 이후 처리와 미게시 작업의 게시를 중단하고 이미 게시한 결과는 유지한다.

## 임시 파일 수명과 정상 종료

원문 HEIC 데이터는 worker 입력용 임시 파일로 준비할 수 있다. 결과는 앱이 관리하는 임시 영역에만 두고 일반 저장 폴더에 자동 누적하지 않는다. 현재 게시된 파일 URL이 참조하는 결과는 붙여넣기에 필요한 동안 유지한다. 성공 직후 결과 파일을 삭제하지 않는다.

새 클립보드로 교체되면 이전 결과의 참조 여부와 worker 종료를 확인해 더 이상 필요한 파일이 아닌 경우 정리한다. 취소·실패한 미게시 작업도 worker가 파일을 사용하지 않는 시점에 정리한다. 원본 파일은 수정하거나 삭제하지 않는다.

정상 종료는 현재 클립보드가 앱이 게시한 세대인 경우에만 원본 스냅샷의 복구를 요청한다. 쓰기 성공 후 임시 결과를 정리하며, 복구 실패 시 현재 클립보드가 참조하는 파일을 먼저 삭제하지 않는다. 사용자가 새로 복사한 내용은 변경하지 않는다. 합성 항목은 종료 후 보존을 확인했다. 후속 실기에서 Photos가 일반 복사로 제공한 JPEG raw 항목은 앱 실행·종료 후 전체 표현의 타입·바이트·세대가 유지됐다. 이 결과는 지원을 제한한 Photos 보관함 URL의 복구를 보장하지 않는다. 비정상 종료 이후 원본 복구는 보장하지 않는다.

## UI와 설정 이행

패널이 숨겨져 있을 때는 메뉴 아이콘 아래의 별도 알림에 복사한 HEIC 수, 처리 진행,
변환 결과를 표시한다. 다른 파일이 섞여 있으면 전체 파일 수와 HEIC 수를 구분한다.
성공은 모든 결과를 현재 클립보드에 반영한 뒤에만 표시한다. 일부 처리에 성공했어도
일괄 반영이 실패하면 실패를 안내한다. 새 복사·끄기·종료 시 이전 알림을 숨기고
이전 작업의 늦은 응답은 새 알림에 반영하지 않는다.

알림은 키보드 포커스를 바꾸지 않는다. 진행 중에는 유지하고 완료는 4초, 실패는 6초
뒤에 닫는다. 클릭하면 현재 클립보드 패널을 열며 닫기 버튼은 해당 작업의 후속 알림도
숨긴다. 열린 패널과 알림은 동시에 표시하지 않는다. 알림은 과거 이력을 보관하지 않는다.
알림은 폭 300pt 안에서 콘텐츠 높이를 측정해 표시한다. 혼합 개수 행·진행 막대·문구의
줄바꿈에 따라 높이가 달라지며 위쪽 메뉴 기준점과 하단 14pt 여백을 유지한다.

좌클릭 패널은 현재 파일의 이름·썸네일·준비/변환 중/완료/실패 및 필요한 거절 상태를 표시한다. 큰 자동 변환 토글은 두지 않는다. 과거 이력을 누적하지 않고 복사 감지로 패널을 자동 표시하지 않는다. 메뉴 아이콘에 연결된 돌출부와 화면 경계 배치는 유지한다. 우클릭 메뉴는 자동 변환 일시정지·다시 시작, 설정 열기와 앱 종료를 제공한다. 일시정지 중에는 메뉴바 아이콘의 정지 기호와 패널의 짧은 안내로 상태와 재개 방법을 알린다.
다른 앱이나 창으로 포커스가 이동하면 패널을 닫으며, 앱을 다시 활성화해도 자동으로 열지 않는다.
메뉴 아이콘을 클릭하면 다시 열린다.

메뉴바와 패널 헤더·빈 상태는 집게가 있는 클립보드 안에 산과 해를 넣은 공통 벡터
아이콘을 사용한다. 메뉴바는 16.2×18pt 단색 템플릿으로 시스템의 밝은/어두운 표시를 따른다.
패널 헤더 아이콘은 흰색 34pt 타일에 회색 선으로 표시하고, 8pt 둥근 모서리와 옅은 회색 테두리를 사용한다.
파일이 있는 패널은 최대 세 행과 하단 안내의 실제 높이에 맞추며 더 긴 목록은 스크롤한다.
파일 수·처리 상태·안내 문구·폭 변경에 따라 측정하고 메뉴 아래의 위쪽 기준점을 유지한다.
사용자가 직접 늘린 높이는 보존하며 빈 목록은 300pt로 접는다.
토글과 설명 행을 제거하고 목록 제목을 헤더 아래에 배치한다. 좌우 여백은 14pt로 통일한다.

키보드·접근성 방식으로 메뉴 아이콘을 활성화하거나 Control 클릭하면 네이티브 메뉴로
진입한다. 메뉴에는 현재 클립보드 보기, 일시정지·재개, 설정·종료가 있다. 앱에 포커스가
있을 때 `⌘1`은 패널 표시(이미 열렸으면 유지), `⌘⇧P`는 일시정지·재개, `⌘,`는 설정,
`⌘W`는 현재 창 닫기, `⌘Q`는 정상 종료다. `Esc`는 패널만 숨긴다. 읽기 전용 목록은
방향키·Page Up/Down·Home/End로 스크롤하며 행별 Tab 포커스를 추가하지 않는다.
설정은 macOS 키보드 탐색 또는 전체 키보드 접근에서 Tab·Shift+Tab·Space로 조작한다.
실행 중인 앱을 Finder·Spotlight에서 명시적으로 다시 열면 패널을 보여 준다.
일반 앱 재활성화와 복사 감지는 패널을 다시 열지 않으며 전역 단축키를 등록하지 않는다.

변환 형식, JPEG 품질, PNG 압축 및 메타데이터 옵션은 별도 설정 창으로 옮긴다. 옵션만 저장하고 일시정지는 해당 실행에만 유지한다. 매 실행은 자동 변환이 켜진 상태로 시작한다. 이전 설정의 꺼짐 값은 실행 상태로 사용하지 않는다. 기본값은 JPEG, JPEG 품질 90, PNG 압축 6, 메타데이터 `safe`이며 이전 설정의 옵션과 수치는 유지한다. 기존 `outputDirectory`와 `onConflict`는 레거시 값으로 보존하되 새 자동 변환 UI에서 제외한다. 설정의 기본값 복원도 화면에 표시한 형식·품질·압축·메타데이터만 초기화하며 이 레거시 값과 실행 중 일시정지를 유지한다. 임시 결과 이름 충돌은 원본을 덮어쓰지 않는 방식으로 처리한다. 기존 CLI/TUI의 저장 경로·충돌 정책에는 이 UI 이행을 적용하지 않는다.

## PR #9 당시 확인한 환경과 미검증 항목 (2026-10-11)

아래는 PR #9 준비 당시의 관찰과 남은 항목이다. 현재 지원 범위는 위 계약을,
후속 결과는 [남은 검증 후속 기록](macos-issue7-remaining-validation.md)을 따른다.

읽기 전용 설치 조사에서 로컬 macOS는 `sw_vers` 기준 27.2, arm64였고 Command Line Tools 경로를 확인했다. Finder·Photos 및 KakaoTalk 26.8.0의 설치만 확인했다. 일반 클립보드 내용과 개인 Photos 사진에는 접근하지 않았으며 앱 간 붙여넣기를 실행하지 않았다.

이후 MOV 문제 조사에서는 사용자 지시에 따라 현재 Photos 동영상 한 항목의 클립보드
타입과 자산 참조 메타데이터를 읽었다. `mediaType=2`와 JPEG 포스터 URL을 확인했다.
보관함 DB·원본 MOV 조회와 수신 앱 붙여넣기는 수행하지 않았다. 재실행 전후에도
이 항목의 클립보드 세대와 타입 목록이 유지됨을 확인했다.

이후 PR 준비에서는 Finder 실제 복사·붙여넣기와 Photos 원본 HEIC, 합성 원본·편집·다중 사진을
검증했다. Finder는 변환 JPEG 1개·3개와 혼합 6개를 중복 없이 붙였다. 혼합 입력의
기존 JPEG·PNG·텍스트 파일은 SHA-256이 원본과 일치했다. 카카오톡 26.8.0은 파일 URL을
선택해 전송 전 미리보기에 단일 1개·혼합 6개를 표시했으며 전송은 취소했다.

Photos 사진이 제공하는 원문 HEIC는 파일 URL보다 우선한다. Photos 파일 URL은
물질화나 확장 속성 읽기에서 지연될 수 있어 입력 읽기·썸네일에 사용하지 않는다.
미리보기가 HEIC가 아닌 JPEG인 경우에는 변환하지 않는다. 일반 파일은 POSIX 메타데이터로
검증하고 dataless 파일은 열기 전에 거절한다. 일반 입력의 URL과 raw 불일치는 여전히 거절한다.

다음 항목은 이번 환경에서 완료로 판정하지 않는다.

- iCloud 미다운로드 자산을 실제로 선택해 다운로드 여부를 관찰하는 검증. 공급자 상태를
  임의로 변경하지 않았다. dataless 거절과 Photos raw 우선은 합성 회귀로 검증했다.
- Photos 드래그의 파일 약속 실기 조사. 일반 복사의 관찰 결과로 대체하지 않는다.
- 카카오톡 실제 전송·수신 결과. 확인 범위는 전송 전 붙여넣기 미리보기다.
- 실제 Photos URL의 정상 종료 후 보존. 독립 복구 도구 종료 후 URL 타입이 사라졌으며
  사진·메타데이터는 보존됐다. 합성 named pasteboard에서는 재현되지 않았고 원인은 미확정이다.
- macOS 15/26의 앱·DMG·테스트 결과는 해당 커밋의 CI 기록을 따른다.
- 대표 이미지가 index 0이 아닌 다중 이미지 HEIC의 네이티브 HDR PNG. 기존 Python 코어의
  `_save_hdr_png()`는 당시 index 0을 사용했다. PR #9 준비 시점에는 Python 코어를 수정하지 않았다.

정확한 실기 조건과 이슈 체크리스트 대응은 [PR 준비 기록](macos-issue7-pr-readiness.md)을 따른다.

## 후속 확인과 현재 제한 (2026-10-12)

사용자가 미다운로드로 지정한 실제 iCloud 사진에서 드래그는 파일 약속과 `public.jpeg`,
일반 복사는 HEIC 없는 JPEG raw를 제공했다. 드래그 타입 관찰은 공급자에게 데이터를
요청하지 않고 수행했다. 다운로드 상태를 독립적으로 검증하거나 공급자 상태를 변경한
결과는 아니다. 일반 복사 JPEG는 HEIC 변환 대상이 아니며 앱 실행·정상 종료 뒤 전체
클립보드 표현이 보존됨을 확인했다.

Python 코어의 `_save_hdr_png()`는 `CGImageSourceGetPrimaryImageIndex`가 반환한
유효한 인덱스를 HDR 디코딩에 사용한다. 실제 생성한 합성 다중 HEIC에서 대표 인덱스가
1이며 첫 이미지에는 게인 맵이 없음을 확인하고 대표 이미지의 16비트·PQ HDR PNG와
메타데이터 정책을 검증했다. 개인 사진은 이 HDR 회귀 테스트의 입력으로 사용하지 않았다.

카카오톡 후속 실기 결과와 최신 자동 테스트 수는
[남은 검증 후속 기록](macos-issue7-remaining-validation.md)을 따른다. 여기서는 채팅
전송·수신 완료를 판정하지 않는다.
