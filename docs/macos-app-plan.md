## 목적

기존 `heic-converter-tui` Python 패키지와 CLI/TUI를 유지하면서, Python 설치 없이 실행할 수 있는 macOS HEIC 변환 앱을 추가한다. 사용자는 메뉴 막대에서 고정 드롭 패널을 열고 HEIC 파일을 드롭하거나 Finder에서 복사한 파일을 대기 목록에 추가한 뒤 파일 저장 또는 이미지 복사를 선택해 변환한다.

첫 지원 대상은 **Apple Silicon arm64, macOS 15 이상**이다. 앱 이름은 **HEIC Converter**, 첫 기능 버전 목표는 **0.3.0**으로 한다.

## 참고 조사

[gksdud](https://github.com/codingnoye/gksdud)는 Swift/AppKit 메뉴 막대 유틸리티다. 조사한 [v1.6.0 릴리스](https://github.com/codingnoye/gksdud/releases/tag/v1.6.0)는 Universal `.app`을 ZIP으로 배포하고 Homebrew Cask를 제공하며, 자체 서명이고 Apple 공증은 받지 않았다.

이 프로젝트에서는 앱 번들 구성, 서명 검증, 릴리스 체크섬과 macOS 빌드 자동화를 참고한다. `.app`과 Applications 바로가기를 DMG로 묶는 단계를 추가한다. 앱 실행 파일을 직접 내려받아 검증한 조사는 아니며, 이 앱은 별도의 Python 런타임·네이티브 의존성 패키징이 필요하다.

## 확정한 사용 흐름

### 메뉴 막대와 고정 드롭 패널

- 앱 실행 중에는 백그라운드에서도 메뉴 막대 아이콘을 유지한다. 고정 드롭 패널을 기본 화면으로 사용한다.
- 아이콘 왼쪽 클릭으로 드롭 패널을 열고 닫는다. 오른쪽 클릭은 네이티브 `NSMenu`를 열어 패널 상태에 따른 “패널 열기”/“패널 숨기기”와 “앱 종료”를 제공한다. 다른 앱이나 바탕화면을 클릭해도 패널을 숨기지 않고 일반 창 위에 유지한다.
- 패널을 열 때 메뉴 막대 아이콘 바로 아래에 배치하고, 아이콘이 있는 화면의 사용 가능한 영역을 벗어나지 않도록 위치와 크기를 조정한다. 기본 크기는 420 × 520포인트, 최소 크기는 380 × 520포인트다. 이전 420 × 600·380 × 560 기준은 대체됐으며 파일 추가·설정 펼침에 따른 자동 높이는 간결한 패널 계획을 따른다.
- 아이콘을 다시 클릭하거나 패널의 닫기 버튼을 누르면 패널만 숨긴다. 숨기기는 앱 종료, 클립보드 감지 중지 또는 진행 중 작업 취소를 의미하지 않는다.
- 변환이 끝나도 패널을 자동으로 닫지 않는다. 사용자 앱 종료 시 메뉴 막대 아이콘과 감지를 함께 종료한다.
- 화면은 SwiftUI로 작성하고 AppKit `NSPanel`에 배치한다. `hidesOnDeactivate = false`와 floating 수준을 사용하며 외부 클릭을 닫기 이벤트로 처리하지 않는다.
- Glassmorphism UI는 macOS 기본 블러와 반투명 카드, 은은한 테두리로 구성한다. 가독성을 위해 네이티브 블러의 alpha는 1, 창 배경의 불투명도는 0.9, 카드의 불투명도는 어두운 모드 0.72·밝은 모드 0.82를 사용한다. 투명도 줄이기와 높은 대비에서는 가독성을 우선한다.
- 추가 설계 기본값으로 Dock에 상주하지 않는 메뉴 막대 앱(`LSUIElement = true`)으로 구성한다. 로그인 자동 실행은 첫 버전에 추가하지 않는다.
- 메뉴 막대에는 대기 파일 수를 표시하고, 패널에서 클립보드 감지 토글, 저장 폴더 열기와 앱 종료를 제공한다. 버튼의 공통 모서리 반경은 10포인트이며 앱 종료는 빨간색으로 표시한다. 대기 목록의 큰 변환 시작 버튼은 50:50 너비의 “변환 후 저장”과 “변환 후 복사”로 나누고 선택 모드는 초록색으로 표시한다. 진행 중에는 각 모드의 변환 예약 동작을 제공한다. 진행·취소와 보조 동작은 별도 행에 두며 닫기 X는 중립적인 스타일과 키보드 포커스 표시를 유지한다.
- 앱 이름·로고·메뉴 아이콘은 [브랜딩 후속 이슈 #5](https://github.com/jaehunshin-git/heic-converter-tui/issues/5)에서 검토한다.

### 파일을 드롭한 뒤의 선택

1. 드롭 존에서 하나 이상의 로컬 HEIC 파일을 받는다.
2. 같은 패널에 파일 목록과 변환 설정을 표시한다. 설정은 초기 접힘 상태로 JPEG·PNG 형식, JPEG 품질 또는 PNG 압축, 저장 위치만 요약한다. 메타데이터와 동일 이름 처리 정책은 설정을 펼치면 표시한다.
3. 사용자가 현재 선택 모드에 따라 **지금 저장** 또는 **지금 복사**, 혹은 **대기 목록에 추가**를 선택한다. **드롭이나 파일 선택만으로 변환하거나 결과를 복사하지 않는다.** 취소하면 이번에 선택한 파일을 추가하지 않는다.
4. 임시 선택 목록의 지금 저장/지금 복사는 이번에 선택한 파일만 현재 모드·설정으로 실행하며 대기 목록의 파일을 포함하지 않는다. 다른 작업이 실행 중이면 다음 작업으로 예약한다.
5. 대기 목록에 추가는 파일만 추가하며 자동 실행하지 않는다. 하단의 50:50 버튼 **변환 후 저장**과 **변환 후 복사**는 임시 선택 파일만 있어도 활성화된다. 누르면 임시 선택 목록과 대기 목록의 파일을 함께 해당 모드로 실행하거나 예약하며 모드와 그 시점의 옵션을 스냅샷으로 고정한다. 드롭 직후 대기 목록에 먼저 추가하지 않고 원하는 모드를 직접 선택할 수 있다.
6. 진행 상태, 성공·건너뜀·실패와 실패 파일 재시도를 제공한다. 파일 저장 결과에는 결과 파일·저장 폴더 열기를 제공하고 복사 결과에는 이미지 복사 상태를 표시한다. 재시도는 항목의 이전 모드를 유지한다.

드롭 영역 클릭과 ⌘O는 표준 Finder 파일 선택창(`NSOpenPanel`)으로 여러 HEIC를 선택해 임시 선택 목록에 추가한다. ⌘V는 복사한 로컬 HEIC 파일을 대기 목록에 추가하는 기존 동작을 유지한다.

입력은 대소문자를 구분하지 않는 `.heic` 로컬 파일로 제한한다. 폴더 드롭, `.heif`, 일반 클립보드 이미지 및 Photos의 파일 약속 데이터는 첫 버전에 포함하지 않는다. 읽을 수 없는 파일과 심볼릭 링크는 제외하고 이유를 표시한다. Photos 미지원 입력에는 Finder로 수정하지 않은 HEIC 원본을 내보내도록 안내한다. 파일 약속 수신은 [후속 이슈 #4](https://github.com/jaehunshin-git/heic-converter-tui/issues/4)에서 다룬다.

선택 파일과 대기 목록의 파일명 왼쪽에 작은 썸네일을 비동기로 표시한다. 크기와 용량을 제한한 메모리 캐시만 사용하며 실패 시 대체 아이콘을 표시한다. 입력 제거·정리·종료 시 메모리를 관리하고 원본과 변환에는 영향을 주지 않는다.

### 클립보드 감지

- 감지 기본값은 켜짐이며 사용자 토글을 기억한다. 패널을 숨기거나 다른 앱을 사용해도 앱 실행 중에는 감지를 유지한다.
- `NSPasteboard.changeCount`를 0.75초 간격으로 확인한다. 변경된 경우 파일 URL만 읽고 HEIC 파일을 대기 목록에 추가한다.
- 새 HEIC 파일이 실제 대기 목록에 추가되면 메뉴 막대 아이콘 아래 패널을 내려오는 느낌으로 표시한다. 이미 열린 패널은 유지하고 포커스를 강탈하지 않으며 자동 변환하지 않는다. 모션 줄이기를 존중한다. 중복·거절 입력, 시작 이전 클립보드, 감지 재개 시 기존 내용과 직접 붙여넣기는 자동 표시 이벤트를 만들지 않는다.
- 감지는 상태 버튼 하나로 표시하며 켜짐은 파란색과 명시적인 상태 글자를 사용한다. 접근 거부 상태는 별도로 안내한다.
- 앱 시작과 감지 재개 시 현재 변경 번호를 기준으로 삼아 기존 클립보드 내용을 자동으로 추가하지 않는다. 직접 붙여넣기 `⌘V`는 유지한다. 이전 별도 붙여넣기 버튼은 제거됐으며 드롭 영역 클릭은 Finder 파일 선택으로 대체됐다.
- 같은 변경 번호를 반복 처리하지 않는다. 기존 목록에 남아 있는 동일 실제 경로의 파일은 드롭·붙여넣기·감지 경로를 통틀어 중복 추가하지 않는다. 사용자가 항목을 제거하면 새 입력으로 다시 추가할 수 있다.
- macOS 15.4 이상의 접근 상태 API는 가용성 조건을 적용한다. 접근 거부 시 자동 읽기를 반복하지 않고 상태와 드롭·직접 붙여넣기 대안을 제공한다.
- 감지·입력·파일 저장 변환은 클립보드를 수정하지 않는다. 명시적인 변환 후 복사 작업만 완료된 이미지 결과를 쓰며 복사 이력은 기록하지 않는다. 파일 목록은 메모리에만 유지하며 앱 종료 시 버린다. 설정과 저장 위치만 저장한다.

### 저장과 작업 관리

- 기본 저장 위치는 `~/Pictures/HEIC Converter`다. 첫 파일 저장 변환 때 생성하고, 사용자가 변경한 위치는 기억한다. 기존 사용자 선택 위치는 보존하고 알려진 검증용 `/private/tmp/heic-converter-ui-check/converted` 설정만 새 기본값으로 복구한다. 사진 파일은 이동·삭제하지 않으며 화면의 홈 경로는 `~`로 표시한다. 생성·쓰기 실패 시 다른 위치를 선택하도록 안내한다.
- 기본값은 JPEG, High 품질(90), PNG 압축 6, 메타데이터 `safe`, 충돌 정책 `rename`이다. `preserve`·`strip` 및 `skip`·`overwrite`·`error`도 선택할 수 있다.
- 앱의 JPEG 품질 선택은 Low(60), Medium(80), High(90, 기본값), Raw(100) 네 단계로 제공한다. 수치는 품질 백분율이 아닌 인코더 설정이다. Raw는 최대 JPEG 품질이며 손실 압축은 유지한다. RAW 파일이나 무손실 출력은 뜻하지 않는다. PNG 압축은 작게(9), 균형(6, 기본값), 빠르게(3), 압축 없음(0) 순서로 표시한다. 픽셀과 화질은 같고 압축 시간과 파일 크기가 달라진다. 네이티브 HDR PNG에는 압축 수준이 적용되지 않는다. 기존 저장 수치와 작업별 설정 스냅샷, CLI/TUI 선택 방식은 유지한다.
- 기존 저장 품질 수치는 프리셋을 직접 선택하기 전까지 변경하지 않는다. 화면에는 가장 가까운 프리셋을 표시하며, 거리가 같으면 높은 품질을 표시한다. 선택한 프리셋은 기존 `jpeg_quality` 수치로 저장하고 worker에 전달한다.
- 파일 저장 모드의 앱 파일 목록 입력은 JPEG/PNG 결과를 지정 저장 폴더에 모으며, 같은 이름은 선택한 충돌 정책으로 처리한다. 기존 CLI의 디렉터리 구조 보존 동작은 유지한다.
- 목록은 항목 제거, 완료 항목 정리와 실패 재시도를 지원한다. 완료 결과를 사용자가 정리하기 전에는 같은 입력을 자동으로 다시 추가하지 않는다.
- 한 번에 한 작업을 순차 실행하고 예약 시 저장·복사 모드, 옵션과 대상 파일을 스냅샷으로 고정한다. 이후 모드·설정 변경은 기존 예약에 영향을 주지 않고 재시도는 항목의 이전 모드를 유지한다. 변환 중 들어온 파일은 별도의 대기 항목으로 유지한다.
- 취소는 현재 파일 처리를 마친 뒤 다음 파일 전에 적용한다. 파일 저장 모드는 완료 결과를 남기고 실행하지 않은 파일을 대기로 되돌린다. 복사 모드는 취소 시 클립보드를 쓰지 않고 임시 결과를 정리하며 복사 대기 결과를 대기로 되돌린다.
- 변환 후 이미지 복사는 이번 PR #3에 포함한다. 이미 저장된 결과 파일의 수동 복사와 결과를 휴지통으로 보내기는 [후속 이슈 #6](https://github.com/jaehunshin-git/heic-converter-tui/issues/6)에 남긴다. 이전의 결과 복사 전체 후속 범위는 이 기준으로 대체한다. 원본 삭제는 허용하지 않는다.
- 복사 모드는 worker 출력 경로를 작업별 임시 job 폴더로 지정하고 완료 결과의 PNG/JPEG 원문을 이미지 데이터(`imageData`)로 읽는다. 이미지마다 별도 `NSPasteboardItem`에 PNG/JPEG 원문과 TIFF 대체 표현을 넣는다. 파일 URL을 복사하지 않으며 지정 저장 폴더에 결과를 남기지 않는다. 성공·취소·실패 완료 시 임시 결과를 정리하고 기존 원본은 보존한다.
- 복사 버튼을 명시적으로 선택한 작업만 worker의 `completed` 이벤트 이후 성공 결과를 게시한다. 결과 0개, 취소 또는 예약·변환 중 다른 내용을 복사한 경우 현재 클립보드를 유지하고 복사 실패·미실행 이유를 안내한다. 이미지 데이터 준비 후 쓰기 직전에도 `NSPasteboard.changeCount`를 확인한다. 자동 감지만으로 변환하거나 결과를 복사하지 않는다.
- 원본은 변경하지 않고, 파일 단위 오류가 다른 파일의 처리를 중단시키지 않도록 한다. 폴더 권한, 삭제된 입력, 이름 충돌과 worker 종료 오류를 사용자에게 구분해 표시한다.

## 공통 엔진과 앱 구조

- CLI에 있는 옵션·경로 검증, 배치 실행, 이름 예약과 충돌 재시도, 오류 처리와 결과 집계를 UI 독립적인 Python 서비스로 추출한다.
- 기존 CLI/TUI의 디렉터리 입력 계약, 옵션, 자연 정렬, 출력 하위 폴더 제외, 종료 코드를 유지한다. 공통 서비스에는 앱을 위한 명시적인 파일 목록 입력을 추가한다.
- 원본 보존, 원자적 저장, 메타데이터 정책과 기존 변환 코어를 재사용한다. 기본 CLI 의존성에 Swift 앱 패키징 도구를 추가하지 않는다.
- SwiftUI는 번들 안의 worker를 `Process`로 실행한다. 셸 명령 문자열이나 사용자 환경의 `python`, Homebrew, `uv`, `pip`에 의존하지 않는다.
- JSONL 요청·이벤트 인터페이스에 프로토콜 버전, 작업 ID, 입력 목록, 저장 위치, 옵션과 취소를 포함한다. 응답은 작업 준비, 파일 시작, 성공·건너뜀·실패, 완료·취소와 집계를 전달한다.
- stdout은 JSON 이벤트, stderr는 진단 출력으로 분리한다. worker를 사용할 수 없거나 프로토콜이 맞지 않으면 실행을 중단하고 오류를 표시한다.
- 기존 HDR 경로와 적용 조건을 유지하고, 파일 결과에 HDR 적용 여부와 SDR 처리 사유를 전달한다. 모든 HEIC의 HDR 보존이나 네이티브 HDR PNG에 압축 수준 적용을 보장하는 문구는 사용하지 않는다.

구현 영역은 `src/heic_converter`의 공통 서비스·worker, `macos`의 SwiftUI 앱, `packaging/macos`의 패키징 설정과 스크립트로 분리한다. 독립된 구현 영역은 서브에이전트에 위임하되 같은 파일의 동시 수정은 피한다.

## 앱 빌드와 배포

- SwiftUI 앱은 Swift Package로 구성한다. 앱 번들 ID는 `io.github.jaehunshin-git.heic-converter`로 고정한다.
- Python worker는 PyInstaller onedir로 묶는다. Python 런타임, Pillow, pillow-heif와 필요한 코덱, PyObjC 및 네이티브 라이브러리를 앱에 포함하고 로더의 상대 경로를 유지한다.
- 빌드 스크립트가 arm64 실행 파일, worker, 아이콘, `Info.plist`, 라이선스 고지를 포함하는 `.app`을 조립한다. Python 버전·의존성은 앱 빌드 환경에서 고정한다.
- 포함된 실행 코드와 앱 번들에 무료 ad-hoc 서명을 적용하고 검증한다. 첫 버전에는 Apple Developer ID 서명과 공증을 포함하지 않는다.
- 완성된 앱과 Applications 바로가기를 담은 DMG 및 SHA-256 체크섬을 생성한다. DMG 포장만으로 Gatekeeper 차단이 없어지지 않으므로 최초 실행 허용 방법을 문서화한다.
- macOS CI에서 Python 검사, Swift 빌드와 worker·앱 패키징 검증을 실행하고 배포 산출물을 만든다. 검증된 DMG는 GitHub Releases, wheel·sdist는 PyPI 배포 대상으로 한다.
- 앱·Python 패키지·GitHub 태그의 기능 버전을 0.3.0으로 맞춘다. 이미 게시된 PyPI 버전의 메타데이터를 덮어쓰지 않는다.
- 앱과 Python 산출물은 각각 허용 목록으로 구성한다. 개인 `input/`, `output/`, 개발 환경과 클립보드 데이터를 포함하지 않는다. 기존 sdist 허용 목록을 유지하고 앱 프로젝트는 GitHub에서 관리한다.
- `README.md`와 PyPI 설명·메타데이터는 영어, `README.ko.md`와 추가 문서는 한국어로 작성한다. 두 README의 기능과 설치 설명을 함께 갱신한다.
- Intel, Universal2, 앱 자동 업데이트, Homebrew Cask와 Mac App Store 배포는 후속 범위다.

## 구현 순서

1. 공통 Python 서비스와 파일 목록 입력을 추가하고 CLI/TUI 호환을 검증한다.
2. JSONL worker와 진행·취소·오류 인터페이스를 구현하고 패키징한 worker를 검증한다.
3. 메뉴 막대 아이콘, 고정 드롭 패널, 드롭 후 선택과 대기 목록을 구현한다.
4. 백그라운드 클립보드 감지와 저장·설정 기억을 연결한다.
5. 내장 worker를 포함한 앱, ad-hoc 서명, DMG와 CI를 구성한다.
6. 설치·변환·배포 파일 검증을 마치고 README와 배포 절차를 갱신한다.

## 최신 PR #3 검증 기준

저장·복사 데이터와 실제 worker·앱·DMG를 검증했다. 오른쪽 메뉴의 액션 연결은 앱 smoke로 확인했고, 메뉴바 우클릭의 전체 시각 검증은 Computer Use가 숨긴 패널을 읽지 못해 수행하지 못했다.

- [x] 오른쪽 클릭 메뉴의 열기/숨기기·종료 액션 연결과 왼쪽 버튼 토글 경로를 앱 smoke로 확인한다.
- [x] 같은 너비의 저장·복사 버튼과 초록색 선택 피드백을 실제 기본 화면에서 확인한다. 최소 너비는 동일한 가변 너비 배치와 기존 패널 크기 회귀를 유지한다. 임시 선택 파일만 있어도 활성화되며 선택·대기 목록을 함께 해당 모드로 실행하거나 예약한다. 지금 저장/지금 복사는 현재 모드로 임시 선택 목록만 실행한다.
- [x] 저장 모드는 설정 폴더에 JPEG/PNG를 저장하며 복사 모드는 원문 이미지 데이터와 TIFF 대체 표현을 이미지별 pasteboard 항목에 넣는다.
- [x] 복사 성공·취소·실패 완료 시 임시 job 결과가 정리되고 지정 저장 폴더에는 결과가 없으며 원본이 보존된다.
- [x] 명시적인 복사 선택과 `completed` 성공 결과에만 클립보드를 쓰고 결과 0개·취소·외부 복사 시 현재 내용을 유지하며 이유를 안내한다.
- [x] 드롭 영역 클릭·⌘O·⌘V 입력을 유지하고 드롭·감지만으로 변환·복사하지 않는다. 지금 저장/지금 복사, 재시도와 예약의 모드·옵션 스냅샷을 유지한다.
