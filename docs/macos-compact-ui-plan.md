# macOS 간결한 패널 UI 개선 계획

- 대상: 이슈 #2, PR #3. main 머지 없이 갱신 후 종료한다.
- 기준일: 2026-10-05
- 상태: 세부 UI 구현, 실제 420×600·최소 380×560 화면, 설정 재시작 복원, 앱/DMG·배포 파일과 macOS 15·26 검증 완료. 최종 PR 검사에서도 같은 검증을 확인한다.
- 참고: Computer Use로 MonoCode 실제 화면을 확인했다. 배경 노출을 억제한 차분한 소재, 선명한 전경, 얇은 테두리와 간결한 컨트롤 배치를 참고한다. 해당 앱의 사용자 문서 내용은 변경하거나 공개하지 않는다.

## 이번 PR

- [x] PNG 표시 순서를 작게(9) → 균형(6) → 빠르게(3) → 압축 없음(0)으로 한다. JPEG의 최대 설정이 오른쪽인 방향과 맞춘다. PNG의 픽셀 품질은 모든 단계에서 동일하다. 기존 숫자·스냅샷은 유지한다.
- [x] 변환 시작과 주요 동작 버튼에 일관된 둥근 모서리 형태를 적용한다.
- [x] MonoCode 화면을 참고해 소재와 카드의 배경 노출을 억제하고 전경 텍스트 대비를 높인다. 투명도 줄이기·높은 대비 경로를 유지한다.
- [x] 변환 설정을 기본 접힘으로 구현한다. 접힌 헤더에는 작은 JPEG/PNG segmented Picker를 두고 품질 또는 PNG 압축과 저장 경로는 한 줄로 요약한다. 펼침에는 형식·품질 선택과 저장 위치 변경을 제공하고 메타데이터·동일 이름 정책은 같은 행에 배치한다. JPEG 인코더 설명은 품질 Picker의 네이티브 help로 제공한다. 펼쳐도 예약된 작업 옵션은 바뀌지 않는다.
- [x] 우측 하단 앱 종료 버튼을 빨간색으로 표시한다.
- [x] 좌측 하단 클립보드 감지를 하나의 상태 버튼으로 통합한다. “클립보드 감지 켜짐/꺼짐” 글자, 색·아이콘, 접근성 이름과 상태를 함께 제공한다.
- [x] 패널 기본 너비를 520 → 420, 높이를 650 → 600으로 조정한다. 빈 초기 화면은 스크롤 없이 표시하고, 선택 파일·긴 목록·펼친 설정은 스크롤로 접근한다. 좁은 크기에서도 컨트롤을 잘리지 않게 배치한다.
- [x] Photos 안내는 드롭존의 가시 텍스트에서 제거하고 help와 거절 메시지에서 유지한다.
- [x] 마지막 변환 설정과 저장 위치를 앱 재시작 시 복원한다. 저장·복원 smoke로 확인한다.
- [x] 최신 수정의 실제 앱에서 접힘/펼침, PNG 순서와 수치, 대비·곡률·종료 색·감지 버튼, 초기 스크롤을 확인하고 Swift/Python·앱/DMG의 합성 변환·macOS 15/26 CI 및 충돌 검증 후 PR을 갱신한다.

## 추가 사용 피드백 반영 계획

위 완료 항목과 검증 기록은 이전 단계의 결과다. 아래 항목은 새 요청의 계획이며 구현과 추가 검증을 마친 뒤 완료 표시한다.

- [ ] 붙여넣기 버튼을 작게 만들고 드롭 영역 가운데에 배치한다.
- [ ] 파일을 놓을 수 있는 영역을 UI와 문구로 분명히 표시하고 마우스 올림과 드롭 진입·이탈에 시각 피드백을 제공한다.
- [ ] 접힌 설정의 JPEG/PNG 선택을 헤더 오른쪽에서 아래 행 왼쪽으로 옮긴다.
- [ ] 저장 경로를 오른쪽 정렬한다. 긴 경로는 앞부분을 `...`로 줄여 뒤쪽 경로가 우선 보이도록 한다.
- [ ] 빈 파일 목록과 그 아래의 여백을 줄인다.
- [ ] 중복 안내의 관련 항목을 삭제한 뒤 안내 상태도 정리한다.
- [ ] 재시도와 정리 버튼을 작게 만든다.
- [ ] 파일 목록에 아이콘을 표시한다.
- [ ] 변환 시작 버튼에 마우스 올림과 누름 상태의 상호작용 피드백을 제공한다.
- [ ] 위 변경을 실제 화면과 관련 회귀 검사로 확인하고 이전 단계 검증과 구분해 기록한다.
