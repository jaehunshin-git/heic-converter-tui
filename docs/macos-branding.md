## 확정 제품 소개 문구

사용자가 승인한 두 줄 문구를 사용한다.

> HEIC를 JPEG·PNG로, 알아서.
>
> 변환은 헤이키에게.

이름 아래의 짧은 기능 설명으로 제안한 `HEIC 자동 클립보드 변환`은 별도 확정 전이다.

현재 앱은 HEIC를 복사하면 설정한 JPEG/PNG로 자동 변환해 클립보드에 준비한다.
변환이 끝나기 전에 붙여넣으면 원본이 전달될 수 있으므로, 최종 문구가 즉시 변환
또는 모든 입력·수신 앱의 지원을 약속하지 않도록 다듬는다.

글자 모양은 Comic Sans MS Regular의 실제 윤곽을 CoreText로 추출한 벡터다.
벡터 편집은 가능하지만 텍스트 입력으로 수정하는 구조는 아니다.
폰트 파일 자체는 프로젝트에 복사하지 않았다.

캐릭터의 중심선 너비:높이는 13.25:17.5, 외곽·입 선 굵기는 1.30, 눈 반지름은
0.72다. 가로 로고에서 28배로 표시하므로 실제 선 굵기는 36.4px이며,
워드마크의 글자 윤곽 높이는 500px다.

원본은 사용자가 내려받은 `~/Downloads/heiccy-lockup-comic-sans.svg`와
`~/Downloads/heiccy-lockup-comic-sans.png`다. 프로젝트에 복사한 두 파일의
이름을 정리했으며, 내용은 Downloads 원본과 바이트 단위로 동일하게 유지한다.

사용자는 1:1 버전에 클립보드 심볼만 넣는 구성을 선택했다. 가로 로고의 심볼 도형을
그대로 재사용하고 1024×1024 캔버스 중앙에 배치했다. 클립보드 자체는 세로로 긴
비율을 유지한다. 캔버스 안의 심볼 외곽은 가로 약 524px·세로 약 677px이며,
상하 여백은 약 174px다. 배경·타일·테두리·글자는 추가하지 않는다.

ICNS에는 같은 투명 심볼을 16·32·64·128·256·512·1024px로 담았다.
`sips`로 크기별 PNG를 만들고 `iconutil`로 묶었으며, 다시 추출한 10개 표현의
크기를 확인했다. 배경이나 모서리 형태는 이 심볼 내보내기에서 추가하지 않았다.
실제 앱 패키징에는 별도의 흰 타일 앱 아이콘을 사용한다.

## 파일 정리

`docs/assets/branding/`에는 확정 가로 로고, 1:1 심볼, 흰 타일 앱 아이콘과 미리보기 HTML·디자인 기준 문서를 관리한다.
선택하지 않은 Excalidraw 시안, 이전 앱 아이콘 PNG·ICNS, 아이콘 조절용 HTML과
이미지 생성 지시 기록은 제거했다. 확정 사항과 남은 작업은 이 문서에서 관리한다.

## 앱 적용과 검증

2026-10-13에 다음 변경을 적용했다.

- 메뉴바는 확정 SVG와 같은 얼굴·외곽 기하를 16.2×18pt 템플릿 이미지로 그린다. 기존 일시정지 배지와 상태 구분을 유지한다.
- 패널 좌상단은 34×34pt 흰 타일 안에 22×24pt 검정 심볼을 넣고 회색 테두리를 제거했다. 비어 있는 패널의 심볼도 공통 기하를 사용한다.
- 앱 아이콘은 1024×1024 캔버스의 흰 라운드 타일 안에 같은 심볼을 배치했다. 타일 바깥은 투명하다. 상세 배치는 [DESIGN.md](assets/branding/DESIGN.md)에 기록했다.
- 패키징은 확정 `heiccy-app-icon.png`에서 크기별 이미지를 생성하고 `AppIcon.icns`로 묶는다. 저장한 `heiccy-app-icon.icns`와 실제 빌드 앱의 ICNS가 바이트 단위로 같다.

로컬 macOS 27.2 arm64에서 Python 테스트 169개와 Swift 테스트 123개가 통과했다.
Swift 테스트는 ConverterKit 76개와 앱 XCTest 47개를 각각 실행했다. 네이티브 심볼과
확정 PNG의 형태 비교, 일반·일시정지 템플릿과 크기별 아이콘 생성도 검사한다.
패키징의 고정 Ruff 환경에서 전체 Python 린트가 통과했다. 앱·DMG 빌드, ad-hoc 서명,
worker 변환, 임시 설치 복사본과 일반 실행·정상 종료 두 번의 검증이 통과했다.

실제 빌드 앱을 열어 현재 어두운 환경의 패널 헤더와 Finder의 앱 아이콘을 확인했다.
컴퓨터 제어 도구가 메뉴바 요소를 화면 밖으로 판단해 실제 메뉴바 클릭은 확인하지 못했다.
자동 검사는 상태 버튼 핸들러와 일반·일시정지 템플릿을 확인하며 WindowServer의 실제
입력을 대신하지 않는다. 밝은 환경과 메뉴바 작은 크기의 육안 검토는 남아 있다.
앱은 메뉴바 전용 앱(`LSUIElement`)이므로 Dock 표시는 확인 대상에서 제외한다.

### 표시 이름 변경 후속 작업 (2026-10-13)

사용자 요청에 따라 앱의 표시 이름, 패널 서비스명, 설정 창 제목, 변환 알림과 앱 메뉴·접근성 이름을 소문자 `heiccy`로 통일했다.
배포 경로는 `dist/macos/heiccy.app`, DMG는 `heiccy-0.3.0-arm64.dmg`와 동일 이름의
`.sha256` 파일이며, DMG 볼륨 이름은 `heiccy`다. CI 산출물 경로도 새 이름을 사용한다.

호환성을 위해 내부 실행 파일 `HEICConverter`, 번들 ID
`io.github.jaehunshin-git.heic-converter`, PyPI 패키지 `heic-converter-tui`와 CLI 명령
`heic-converter`, 기존 `~/Pictures/HEIC Converter` 출력 폴더는 유지한다.

이름 변경 후 같은 로컬 macOS 27.2 arm64에서 Python 169개·Swift 123개 테스트와
고정 Ruff 검사를 다시 통과했다. `heiccy.app`과 `heiccy-0.3.0-arm64.dmg`를 새로 빌드해
표시 이름, 서명, worker 변환, 정상 실행 두 번과 임시 설치 복사본을 검증했다.
실제 실행한 새 앱의 패널 헤더·창 이름·앱 메뉴가 `heiccy`이고, 설정 창 제목이
`heiccy 설정`임을 확인했다. 실제 메뉴바 입력과 밝은 환경의 육안 검토는 앞서 기록한 대로 남아 있다.
이슈 #5의 첫 번째 작업 전체는 아직 완료되지 않았다.

### 메뉴바 얼굴 보정 (2026-10-13)

사용자가 메뉴바에서 눈과 입이 작아 잘 보이지 않는다고 알려 메뉴바용 얼굴을 보정했다.
18×20 기하 좌표계에서 눈 반지름을 0.72에서 1.10으로 키우고 눈의 높이를 10.2로 올렸다.
입의 중심선 폭은 2.30에서 4.00으로 넓히고 선 굵기는 1.30에서 1.50으로 조정했다.
곡선의 깊이와 눈·입 간격도 늘렸다. 메뉴바 출력 크기와 클립보드 외곽, 패널과 앱 로고의
원본 얼굴은 유지한다. 상세 수치는 [DESIGN.md](assets/branding/DESIGN.md#메뉴바)를 따른다.

실제 AppKit 렌더러로 일반·일시정지 상태를 1x·2x PNG로 만들고 밝은·어두운 배경에서
비교했다. 일반 상태의 눈 두 개와 미소가 두 배율 모두에서 서로 떨어진 세 영역으로
그려지는 것을 확인했다. 이 비교는 시스템 메뉴바의 실화면 캡처가 아닌 렌더 검토다.
Swift 테스트 123개가 통과했으며 원본 심볼과 패널 기하의 일치 검사도 유지한다.
새 앱·DMG를 빌드해 서명, worker 변환, 일반 실행 두 번과 임시 설치 복사본을 검증했고,
개선한 `dist/macos/heiccy.app`을 다시 실행했다. 비교 이미지는 로컬 빌드 폴더의
`build/macos/branding-review/menu-bar-face-comparison.png`에 저장했다.

### 패널 서비스 글꼴 적용 (2026-10-13)

패널 헤더의 시스템 글꼴 `heiccy`를 확정 Comic Sans MS Regular 워드마크로 바꿨다.
`heiccy-logo.svg`의 글자 경로 163개를 `HeiccyWordmark.swift`의 벡터 도형으로 옮기고,

별도의 UUID 도메인에 구 코드가 합성 설정을 저장하고 새 코드가 다른 프로세스에서
전체 필드를 읽은 뒤 저장·재읽기하는 검사도 통과했다. 읽기만 한 뒤 저장 바이트가
변하지 않는 것을 확인했고, 격리 도메인은 검사 후 정리했다. 실제 사용자 도메인도
조사 전후 동일했으며 개인 설정값·경로는 문서에 공개하지 않는다.

21개 테스트의 재현 필터는 다음과 같다. 이 건수에는 앞서 별도 확인한 아이콘 3개가
포함되며 합산하지 않는다. 격리 업그레이드 검사는 자동 테스트 건수에 포함하지 않는다.

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
```

legacy `clipboardEnabled` 필드는 보존하지만 실행 중 자동 변환은 시작할 때 활성화된다.
이는 브랜딩 이전부터 유지한 정책이다. 이번에는 임시 설치 경로에서 실제 앱으로 다음 절차를 추가 수행했다.

1. 기존 0.3.0 앱의 복사본을 임시 `Applications/HEIC Converter.app`에 놓고 실행했다.
2. 실제 설정 창에서 기존 옵션을 확인하고 앱 메뉴로 정상 종료했다.
3. 구 앱 복사본을 해당 Applications 밖의 백업 폴더로 옮긴 뒤 새 1.0.0 앱을 설치했다.
4. 새 설치 복사본의 서명 무결성을 확인하고 실제 앱을 실행해 같은 설정 UI를 확인했다.
5. 정상 종료 후 원래 빌드 경로의 동일한 1.0.0 앱을 재실행해 설정 유지를 확인했다.
6. 실제 사용자 도메인 내용과 `converter.settings` 저장 바이트가 조사 전후 동일함을
   해시로 확인했다. 옵션을 바꾸거나 기본값 복원을 누르지 않았다.
