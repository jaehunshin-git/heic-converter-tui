# Python 패키지와 macOS 앱의 저장소 분리 운영

- 결정일: 2026-10-18 KST
- 상태: 사용자 확정, 현재 저장소의 Python 전용 구성 반영 완료
- 후속 결정: [Python 저장소 공개 운영](2026-10-18-python-repository-public.md)

## 결정

두 저장소를 제품별로 독립 운영한다. 각 제품의 개발·문서·이슈·PR·테스트·배포는
담당 저장소에서 관리하며 같은 제품의 코드를 양쪽에서 계속 동기화하지 않는다.

| 저장소 | 담당 제품 | 배포 결과 |
| --- | --- | --- |
| `heic-converter-tui` | Python CLI/TUI | PyPI의 `heic-converter-tui` |
| `heiccy` | Swift macOS 앱 | `heiccy.app`·DMG·GitHub Releases |

Python 패키지명 `heic-converter-tui`와 실행 명령 `heic-converter`를 유지한다.
앱과 패키지의 버전·태그·릴리스 일정은 독립적으로 관리한다.
기존에 게시한 패키지·태그·릴리스를 덮어쓰거나 재작성하지 않는다.

이 결정은 `heiccy`를 두 제품의 단일 개발·배포 원본으로 삼고 현재 저장소를
과거 기록 전용으로 유지하던 방침을 대체한다.

## 배경과 선택 이유

초기에는 비공개 개발 저장소에서 공개 `heiccy`로 소스를 내보냈고 이후 단일 저장소로
통합하려 했다. 그 뒤 앱 변환 엔진을 Swift와 macOS Image I/O로 전환하면서 앱 실행에
Python 패키지가 필요하지 않게 됐다.

두 제품의 실행 엔진·사용 방식·배포 경로가 다르므로 저장소를 나누어 변경 범위와
배포 책임을 명확히 한다. Python 변경으로 앱 빌드·버전 갱신이 발생하는 구조도 없앤다.
두 저장소의 설정과 이미지·메타데이터 정책을 각각 검토하는 비용은 수용한다.
양쪽 구현이나 변환 결과가 항상 같다고 가정하지 않는다.

## 유지할 경계

- 현재 저장소는 Python 제품의 개발·배포 원본이다. Python에 필요한 macOS HDR 검사와
  `worker` JSONL 호환 계약을 유지한다.
- 앱 코드·DMG·앱 릴리스는 `heiccy`가 담당한다. 앱 빌드·서명·검증에 필요한 Python
  도구는 남길 수 있으며 PyPI 제품 코드와 구분한다.
- `heiccy`의 제품 분리가 끝나면 해당 저장소에서 Python 제품의 wheel/sdist를 만들거나
  PyPI에 배포하지 않는다.
- 과거 앱 소스·문서·검증 자료는 Git 이력에서 확인한다. 기존 릴리스와 초기
  `SOURCE.json`의 기준 커밋·해시는 출처 기록으로 유지한다.
- 사진·개인 입력·출력·비밀정보는 Git이나 배포 파일에 추가하지 않는다.

## 후속 결정과 공개 안내

결정 당시의 비공개 유지와 공개 창구 미확정 방침은 후속 공개 운영 결정으로 대체됐다.
현재 Python 제품의 공개 소스·문서·이슈 창구는 이 저장소다. 앱 저장소를 Python 제품의
창구로 안내하지 않는다. PyPI 설명과 배포 메타데이터는 영어를 유지한다.

기존에 정했던 앱 CI 복구 선행 조건도 후속 사용자 지시에 따라 현재 저장소의 반영
조건에서 제외됐다. 앱 CI 복구와 기본 브랜치 반영은 별도 작업으로 남긴다.
