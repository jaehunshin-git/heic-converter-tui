# 이슈 #7 PR 준비 기록

## 변경 결과

HEIC를 복사하면 설정한 JPEG/PNG로 자동 변환해 기존 붙여넣기에 준비한다.
스냅샷·복사 세대·일괄 게시로 원본과 새 복사를 보호하며 정상 종료 때 원본을 복구한다.
좌클릭 패널에는 현재 파일과 자동 변환 스위치만 두고 옵션은 별도 설정 창으로 옮겼다.
변환 알림, 작은 콘텐츠 맞춤 패널, 사진 클립보드 아이콘, 포커스 이동 시 닫힘을 적용했다.
Python 코어·CLI/TUI와 버전은 변경하지 않았다. 앱과 Python 패키지의 배포 검증을 분리했다.

## 실제 앱 검증 (2026-10-11)

환경은 macOS 27.2 arm64, Finder와 Photos, 카카오톡 26.8.0이다.
합성 사진은 로컬 검증 폴더에서 생성했다. Photos에는 합성 사진 3개를 전용 검증 앨범에
가져와 한 장만 뒤집기 편집했다. 기존 사진과 보관함 설정은 변경하지 않았다.
카카오톡은 나와의 채팅의 전송 전 미리보기까지만 확인하고 취소했다.
일반 클립보드는 검증 전 전체 표현을 비공개 로컬 파일에 보존한 뒤 검증 종료 때 복구했다.
개인 사진·클립보드 데이터·자산 식별자를 저장소나 배포물에 넣지 않았다.

| 입력·대상 | 확인 결과 |
| --- | --- |
| Finder HEIC 1개 → Finder | JPEG 1개, 중복 없음 |
| Finder HEIC 3개 → Finder | JPEG 3개, 중복 없음 |
| HEIC 3개 + JPEG·PNG·텍스트 파일 → Finder | 총 6개, 비HEIC 파일 SHA-256 일치 |
| 변환 JPEG 1개 → 카카오톡 | 파일 URL 선택, 전송 전 파일 1개 표시 |
| 혼합 6개 → 카카오톡 | 전송 전 파일 6개 표시, 중복 없음 |
| Photos 원본 HEIC 복사 | 자산 종류 1과 raw HEIC 확인, 수정 후 JPEG 게시 |
| Photos 합성 원본·편집 사진 복사 | JPEG 표현, HEIC 재변환 없이 보존 |
| Photos 합성 원본·편집 혼합 3장 → Finder | JPEG 항목 3개가 파일 3개로 붙음 |
| Photos MOV 복사 | 자산 종류 2의 JPEG 포스터, 변환 제외 |

## PR 전에 수정한 결함

- 클립보드 항목 조회가 실패하면 참조 부재를 단정하지 않고 게시 결과 파일을 보존한다.
- 원본 이름이 255바이트여도 내부 staging 이름을 200바이트 이내로 제한해 worker의
  원자 저장 파일명 예산을 확보한다. 표시·원본 복구는 원래 이름을 유지한다.
- Photos 원문 HEIC가 있으면 Photos URL의 물질화나 확장 속성 조회를 기다리지 않는다.
  실제 조사에서 기존 앱의 메인 스레드가 `getxattr`에서 수 분간 대기한 것을 확인했다.
- POSIX 메타데이터로 일반 파일을 검증하고 dataless 파일은 열기 전에 거절한다.
  실패 미리보기와 비HEIC 항목도 위험한 파일 URL을 썸네일에 전달하지 않는다.
- 패키징은 HFS+ UDZO를 사용하고 이미지 생성·GUI 준비·검증 단계에 시간 제한을 적용한다.

## 검증 근거

- Python 회귀 136개와 Ruff 통과.
- Swift XCTest 93개: 모델 21개, worker 3개, ConverterKit 69개.
- 실제 worker의 JPEG/PNG·255바이트 ASCII/한글/emoji·중복 입력 변환 smoke 통과.
- 앱·DMG, arm64 Mach-O 44개·서명·로더, 사용자 Python 없는 환경의 SDR/HDR 검증.
- wheel/sdist의 영문 설명·버전·허용 목록 검증. Python 배포물에는 macOS 전용 소스와
  개인 사진을 포함하지 않는다.
- macOS 15/26 결과는 동일 브랜치 HEAD의 GitHub Actions 실행에서 확인한다.

## 아직 완료로 표시하지 않는 항목

- iCloud 미다운로드 사진의 실기: Photos가 raw를 제공할 때의 처리는 회귀와 실기 HEIC로
  확인했으나, 실제 자산의 다운로드 상태는 확인하지 않았다. 보관함 저장 설정을 바꾸지 않았다.
- Photos 드래그 파일 약속의 실기: 일반 복사 관찰과 합성 promise 거절 테스트로 대체하지 않는다.
- 카카오톡 실제 전송·수신: 붙여넣기 준비 검증과 구분한다.
- index 0이 대표 이미지가 아닌 다중 이미지 HEIC의 HDR PNG: 기존 코어 범위이며 미검증.

## PR 제출용 설명

제목: `feat(macos): HEIC 자동 클립보드 변환과 미니멀 메뉴바 UI`

HEIC 복사 후 수동 변환 없이 기존 붙여넣기로 JPEG/PNG를 전달하도록 macOS 앱을 바꾼다.
원본 스냅샷과 복사 세대로 전체 게시를 보호하고, 실패·새 복사·끄기·종료 시 유효하지 않은
결과를 게시하지 않는다. MOV와 Photos 동영상 포스터는 변환하지 않는다.

좌클릭 패널을 현재 파일·상태·스위치로 줄이고 설정을 별도 창으로 옮겼다.
메뉴 아래의 진행·완료·실패 알림과 콘텐츠에 맞는 패널 높이, 포커스 이동 시 닫힘을 추가했다.

검증은 위 자동 테스트와 Finder/Photos 실기, 카카오톡 전송 전 미리보기다.
미다운로드 iCloud·Photos 드래그·실제 채팅 전달은 미검증으로 명시한다.
